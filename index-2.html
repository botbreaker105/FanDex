Advanced Battle Systems Reference

Framework notes for the mechanics wired into the Battle Simulator engine. Set these fields on a move (or its "Generate Shield" effect) from the Move Editor, or by hand-editing an exported JSON entry. Every example move below is now live in the starter roster — not just documentation — so you can open a creature's Moves list or run a Battle Simulator match to see it actually resolve: Molten Moat on Emberling, Bramble Ward, Last Stand Slam & Shell Retort on Mossapod, Static Bulwark, Afterimage Strike & Velocity Fang on Voltispire, and Shadow Ember & Executioner's Mark on Umbra Cindrake. Any move carrying one of these mechanics also now shows a matching pill and a "⚙" summary line on its card.

1. Shield / Barrier Tags & Reactive Triggers

A move's "Generate Shield" effect now carries a Reaction field (shieldReaction) with three settings: None (a purely defensive barrier), Direct Damage — reflects shieldReactionValue% of the shield-owner's max HP onto whoever gets blocked (a Thorns/Spikes-style punish) — or Status Infliction — inflicts shieldReactionStatus on the attacker instead, gated by shieldReactionChance. By default the reaction only fires against moves tagged "contact" (shieldReactionContactOnly), so ranged attacks aren't punished by a physical barrier.

Bramble Ward — Grass, Shield

Raises a thorned barrier for 3 turns. Any contact move that hits it reflects 12.5% of the user's max HP back onto the attacker. Reaction: Direct Damage, Contact Only.

Molten Moat — Fire, Shield

Surrounds the user with a ring of magma that absorbs 4 hits. Contact moves that strike it have a 60% chance to Burn the attacker. Reaction: Status Infliction (Burn), Contact Only, Chance 60%.

Static Bulwark — Electric, Shield

A crackling energy wall that blocks 2 hits of any category (not just contact). Every blocked hit has a 100% chance to Paralyze the attacker. Reaction: Status Infliction (Paralysis), Contact Only = off.

2. Accuracy, Dodge & Precision

A move's own accuracy value (0–1) is now multiplied by a live Dodge factor computed from both fighters' effective Speed (base stat × active stat stage) before the hit roll: finalHitChance = accuracy × dodgeMult, where dodgeMult = clamp(0.5, 1.2, 1 − ((defSpeed − atkSpeed) / (defSpeed + atkSpeed)) × 0.5). Equal Speed leaves accuracy untouched; a much faster target is meaningfully harder to hit (down to a 50% floor), and a much faster attacker gets a small bump (up to a 120% ceiling) — Speed always matters, but a move's base Accuracy is never made pointless. Tag a move unavoidable (or undodgeable) to skip this multiplier — and the accuracy roll entirely — so it always connects, Shadow Ember-style.

Dodge Chance. A move field (0–100%, default 0) that raises its USER's own chance to dodge whatever the opponent throws at them THAT SAME ROUND — layered on top of the Speed-based dodgeMult above, not a replacement for it: totalDodgeMult = dodgeMult × (1 − dodgeChance). It's read off whichever move a fighter picks that turn, so it's only active for rounds they actually use the evasive move — a Quick Attack-style move a fighter can lean on repeatedly, not a one-time buff. When it's specifically the Dodge Chance (not raw Speed) that turns a would-be hit into a miss, the log calls it out by name instead of the usual Speed-dodge line: "[Defender] used [Move] and dodged the attack!" — naming the evasive move itself rather than the attacker's move, so it's clear at a glance which fighter's own tech saved them.

Velocity Fang — Normal, Dodge Chance 35%

A frenzied, blink-fast bite — using it also gives its own user a 35% bonus chance to dodge the opponent's attack that same round. Field: dodgeChance: 35.

Executioner's Mark — Dark, Unavoidable

A curse-laced strike that always finds its target regardless of Speed or evasion. Tags: unavoidable.

3. Speed-Scaling Offense

A move's speedScaling field selects a paradigm, with speedScalingFactor (default 0.5) tuning the strength — applied as a straight multiplier alongside type effectiveness and the other damage modifiers:

  • relativeFaster — bonus damage that scales with how much faster the user is than the target this turn; caps at +factor once the user is ~2× the target's Speed.
  • relativeSlower — bonus damage that scales with how much slower the user is than the target; rewards outlasting a faster foe before striking.
  • absolute — base power scales directly off the user's own raw Speed stat, independent of the target entirely.
Afterimage Strike — Fighting, Relative (Faster)

Vanishes and reappears behind the target. Deals up to 50% bonus damage the faster the user is compared to the target. speedScaling: relativeFaster, factor 0.5.

Last Stand Slam — Ground, Relative (Slower)

A crushing counter-blow that hits harder the more the user is outsped by its target. speedScaling: relativeSlower, factor 0.6.

Velocity Fang — Normal, Absolute

A frenzied bite whose force scales purely with the user's own raw Speed. speedScaling: absolute, factor 0.5 (roughly +0.5% power per Speed point).

4. Move Priority & Counter Mechanics

Every move now carries a priority value from -3 to +3 (default 0), set from the dropdown next to Type/Category in the Move Editor. Before Speed is ever checked, both fighters' chosen moves are compared: whichever priority is strictly higher acts first that round, full stop — a +1 priority move always beats a 0-priority move even against a much faster opponent. Equal priority on both sides falls back to the existing Speed-based order untouched. An ability's First-Strike Priority Hook (Tailwind-style) is checked afterward and can still override the result.

A move flagged with Counter Mechanics (counterMove.enabled) throws out its own Base Power entirely. Instead, the engine tracks each fighter's turnState — the exact damage amount and damage type (Physical/Special) it was hit with THIS round — and the Counter move reflects counterMove.multiplier× that number straight back at the attacker, completely bypassing the target's Def/SpD stat and stage changes (the output comes from the incoming damage number, not a fresh atk/def calculation). counterMove.damageType gates which incoming hits it can answer: physical (Counter-style), special (Mirror Coat-style), or any (Metal Burst-style, answers either). If the user wasn't hit at all this round, or was hit by a damage type that doesn't match the filter, the move simply fails with no damage and no secondary effects. turnState is wiped clean for both sides at the end of every round, so a Counter move can never reach back into a previous turn's hit.

Shell Retort — Ground, Counter, Priority -3

Braces behind its shell and slams back with double whatever physical damage it just took this round. counterMove: damageType physical, multiplier 2. Set to -3 priority so it always resolves last — after the hit it's answering has already landed.

5. Terastallization (Manual Item Activation)

An item can now carry a teraType and a teraMove alongside a ON_USER_INTENT effect (trigger: "onUserIntent", action: "terastallize") — a manual-activation category distinct from the existing battleStart/onUse/turnEnd/onTakeDamage/onDealDamage triggers, meant to be popped during turn selection rather than fired off a passive condition. Once per battle, activateTeraState() validates the trigger, swaps the holder's typing to teraType, and injects the item's Dynamic Move (Tera Blast by default — its Type always matches the holder's current Tera Type and its Physical/Special category is recalculated live from whichever of the holder's Attack or Sp. Atk is higher) into the holder's active moveset for the rest of the fight via injectTemporaryMove(), which never touches the holder's stored/base movepool.

STAB is recalculated Tera-aware from that point on: a move matching the new Tera Type gets 2× if that type was also one of the holder's original types, or the standard 1.5× otherwise; a move matching one of the holder's ORIGINAL types still gets its standard 1.5× even after Terastallizing. The special Stellar Tera Type is the one exception — it doesn't overwrite the holder's typing at all, it just guarantees every one of the holder's own move types keeps its normal STAB.

Tera Orb — Held Item, teraType: configurable

Once per battle, Terastallizes the holder into the Orb's configured Tera Type and injects Tera Blast. See the Item Dex for the full effect row.

6. Multi-Hit Scaling

Any move with a Hits Count above 1 now carries a multiHitScaling field (Flat / Ramp Up / Ramp Down) plus a multiHitScalingPct percentage, set right next to the Hits Count dropdown in the Move Editor. Flat is the original behavior — every hit rolls the same Base Power. Ramp Up/Down scale each hit AFTER the first by ±multiHitScalingPct%, compounding per hit — a 3-hit Ramp Down move at 20% deals its 1st hit at full power, its 2nd hit at 80%, its 3rd hit at 64% (0.8²), not a flat 60%. Each hit still rolls its own independent crit/accuracy/variance exactly as before — only the Base Power scaling is new.

Example — any move, Hits Count 5

Ramp Up at 15%: hits land at roughly 100% → 115% → 132% → 152% → 175% of base power — a flurry that builds momentum. Ramp Down at 15% (Triple Kick/Triple Axel-style, but 5 hits and tunable): 100% → 85% → 72% → 61% → 52% — a strong opener that tapers off.

Utility & Hybrid Ability Systems Reference

A second layer of mechanics built on top of the core engine above — blurring the line between Move and Ability, spreading status around the field, and locking a fighter into a multi-turn commitment.

1. Blurring Abilities & Moves

Active Abilities. An Ability flagged manualCast stops being purely reactive (gated on a condition like "HP below 33%") and is folded straight into its owner's movepool as a real, selectable action for the rest of the fight — with its own PP (manualCastPP), Cooldown (manualCastCooldown), and either an attack profile (manualCastCategory Physical/Special + manualCastBasePower/manualCastType/manualCastAccuracy) or a pure Status-category cast that just runs the ability's own effects array — the same Dynamic Multi-Effect Sequence Array a Move uses, so a cast ability can raise a hazard, buff a stat, inflict a status, or anything else a move effect can do. Edge case: if the ability's condition-based passive/active triggers are ALSO configured, both can coexist — the automatic trigger still fires reactively, while manualCast additionally makes it choosable as its own turn.

Passive Moves. Any Stat Modifier or Field Hazard effect set to 0 duration is already permanent by default in this engine — once a move lands it, the buff/debuff/hazard just sits there without needing to be re-selected. The "Passive Move" pattern here is simply a Status-category move whose entire payload is one of these zero-duration effects: cast it once, then spend future turns on other moves while it keeps working in the background. Edge case: a hazard or stat mod set to a fixed positive duration will still expire normally — "passive" and "permanent" aren't the same setting, use duration 0 deliberately for the latter.

Overclock Vent — Electric, Active Ability

Normally a passive that boosts damage below 33% HP — but flagged Manually Castable lets the user vent it early as a Special attack (Type Electric, BP 70, Acc 100%, PP 5, Cooldown 3) instead of waiting for the HP threshold.

Root Anchor — Grass, Passive Move

A Status move that raises the user's Defense and Sp. Def by 1 stage with Stat Modifier Duration set to 0 (permanent) — cast once at the start of a fight and never needed again.

Caltrop Field — Ground, Passive Move

A Status move using the Field Hazard effect (non-stacking, flat damage) to lay a permanent entry hazard on the opposing field with a single cast.

2. Specialized Status & Omni-Boost Mechanics

Status Transfer/Swap. A move using the new Status Transfer/Swap effect can give the user's own status to the target (curing the user), steal the target's status onto the user (curing the target), or swap whatever both sides currently carry — including a status-free side wiping the other's condition entirely. Edge case: a transfer that would land on a type immune to that status (e.g. moving Burn onto a Fire type) simply fizzles and the original holder keeps it — it never destroys a status just because the destination can't accept it.

Omni-Boost Secondary Effects. The new Omni-Boost effect raises Atk/Def/Sp.Atk/Sp.Def/Speed by the same number of stages simultaneously, gated by the same per-effect Chance roll every other secondary effect already uses (10%, 30%, 100%, whatever the move calls for). Edge case: an ability that blocks stat drops/raises on a given side is checked stat-by-stat — if it blocks buffs entirely, the Omni-Boost simply does nothing to that side that turn rather than partially applying.

Plague Kiss — Poison, Status Transfer

Transfer Mode: steal. Rips whatever status condition the target is carrying and inflicts it on the user's own opponent-facing side instead — a desperation cure for the user disguised as an attack.

Contagion Trade — Poison, Status Transfer

Transfer Mode: swap. The user hands its own Badly Poisoned counter to the target in exchange for whatever (if anything) the target was dealing with.

Ascendant Surge — Fairy, Omni-Boost

A support move with a 10% chance (Omni-Boost, +1 stage, Target Self) to raise all five primary stats at once alongside its normal minor healing effect.

3. Multi-Turn Lock-In Attacks

Apply the existing Repeat status (Status Overlay effect, Status Effect = Repeat, Duration 2–3 turns) to the user itself on cast: while it's active, move-selection is forced to keep re-using whatever move was just used, bypassing normal AI pool selection entirely. When the Repeat status's duration runs out, its configured Lock-In End Effect pays off automatically: confusion (default — Outrage/Thrash-style, the user snaps out of the frenzy and becomes Confused for 2–3 turns), cooldown (the just-repeated move is locked out for lockInCooldownTurns instead of confusing anyone), or none (a clean end with no drawback, for a lower-risk lock-in). Edge case: if the locked move runs out of PP mid-lock, selection falls through to normal rules for that turn (Struggle if nothing else is usable) — but the Repeat status itself keeps ticking down and still pays off its end effect on schedule even if a turn or two were spent elsewhere.

Frenzied Gale — Flying, Lock-In

A powerful Physical attack that applies Repeat to the user for 2–3 turns. Lock-In End Effect: confusion (default) — the user thrashes on repeat, then staggers dazed once the storm passes.

Overdrive Barrage — Steel, Lock-In

Fires on repeat for 3 turns at high Base Power. Lock-In End Effect: cooldown (2 turns) — the mechanism needs to physically cool down afterward instead of confusing its pilot.

Trance Dance — Psychic, Lock-In

A lower-commitment 2-turn lock-in with Lock-In End Effect set to none — a safer option for a moveset that wants the repeat-attack pressure without the usual drawback.
